# MoveBeat Track Assistant для Android

Это ранняя версия Android-клиента. В исходниках реализованы:

- поиск карт через публичный BeatSaver API;
- загрузку только с HTTPS-доменов BeatSaver;
- лимиты размера и защиту от path traversal/дублирующихся имён в ZIP;
- каноническую проверку BeatSaver content SHA-1 для v2/v3/v4;
- просмотр сложностей и сохранение проверенного ZIP через Storage Access Framework;
- импорт локального ZIP или загрузка по ключу BeatSaver с экспортом готового
  MoveBeat bundle ZIP (внутри папка уровня с `level.ini`, `.mbchart`, Ogg/Vorbis,
  обложкой, уменьшенной карточкой `library.mblc` и отчётом с хешами).

Конвертер переносит ноты, бомбы, стены, цепочки, дуги и BPM-события из v2/v3/v4.
Как и ПК-версия по умолчанию, он выбирает сложности `Standard` и отказывает
при аудио не в Ogg/Vorbis. Bundle ZIP нужно распаковать: папка внутри него —
готовый уровень для `USRDIR/levels/<id>/` или для передачи через FTP.

В Android-прототипе есть поиск и явный выбор карты из результатов, загрузка и
подготовка BeatSaver ID/ключа, импорт локального ZIP и экспорт готового bundle
через системный диалог файлов. Добавлена передача подготовленного уровня на
FTP-сервер PS3: приложение показывает фиксированный путь библиотеки, требует
явного подтверждения перед передачей, использует скрытый staging-каталог,
читает файлы обратно и сверяет SHA-256 перед атомарной публикацией. Существующий
ID не заменяется. Пароль FTP не сохраняется; интерфейс предупреждает, что
обычный FTP передаёт пароль и файлы открытым текстом. Передача предназначена
для доверенной локальной сети.

Debug APK собран и установлен в Android 36 эмулятор `MoveBeat_API36`. В текущем
ручном UI smoke проверены ввод `!bsr 54851`, поиск/автоподстановка ID, загрузка,
конвертация в один Expert-чарт и появление системного диалога сохранения; ZIP
в этом прогоне не сохранялся. Форма FTP отображается вместе с предупреждением.
Три JVM-теста
покрывают публикацию, отказ при конфликте ID и уборку staging-каталога после
ошибки проверки. SHA-256 проверенного APK:
`DF5A66FE74A437CA64776C8C8D2729FA35B37209B4C26BF3856986FA20F85E74`.
Передача через Android UI проверена end-to-end с локальным FTP-макетом: staging,
STOR/RETR сверка SHA-256, атомарный RNFR/RNTO и очистка пароля завершились
успешно; финальный bundle прошёл `tools/validate_bundle.py`. Реальный FTP-сервер
на PS3 и физическое Android-устройство ещё не проверялись; полноценная локальная
библиотека с карточками/обложками также остаётся планом.

Формат конвертера можно проверить без Android SDK: тест
`tests.test_android_parity` компилирует Kotlin-ядро на JVM с временной
заглушкой рисования карточки, сравнивает `level.ini`, `.mbchart` и отчёт с
ПК-конвертером на v2/v3/v4, а общий код упаковки RGB565 проверяет
байт-в-байт по эталону. Там же проверяется правило автоподстановки: только
однозначный прямой ID/ключ может выбрать карту автоматически; результаты
текстового поиска требуют явного нажатия. Для теста нужны Kotlin CLI, Java и JAR
`org.json:json:20250517`; путь к JAR задаётся `ORG_JSON_JAR`. Заглушка не
проверяет Android-отрисовку обложки и шрифтов. JVM-тесты ранее прошли для всех
трёх версий карт и для дополнительно проверенного реального архива `461fa`.
Повторный запуск parity-тестов после текущего изменения требует этот JAR.

Проект настроен на Android Gradle Plugin 9.4.0, Gradle 9.6.0, `compileSdk=36`,
`minSdk=26`. Для сборки необходимы JDK 17+, Android SDK Platform 36 и Build Tools
36.1.0. В `C:\Users\Nikpo\AppData\Local\Android\Sdk` установлены Platform 36,
Build Tools 36.1.0, platform-tools и Android 36 Google APIs x86_64 emulator;
SDK-лицензии приняты.

Сборка:

```powershell
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat :app:assembleDebug --no-daemon --non-interactive
```

Результат: `app/build/outputs/apk/debug/app-debug.apk` (debug-signed; package
`io.movebeat.assistant`, minSdk 26). Для unit-тестов используется команда
`.\gradlew.bat :app:testDebugUnitTest --no-daemon --non-interactive`.
Подпись APK проверена `apksigner`; приложение установлено в Android 36 AVD
`MoveBeat_API36`.
